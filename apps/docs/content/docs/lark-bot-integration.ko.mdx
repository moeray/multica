Multica 에이전트를 Feishu Bot으로 연결하면 팀 멤버가 Feishu에서 에이전트와 DM을 나누고 그룹에서 @멘션하거나 `/issue`로 태스크를 만들 수 있습니다. 대화와 실행 기록은 계속 Multica 워크스페이스에 저장됩니다.

Bot 하나는 에이전트 하나에만 대응합니다. Feishu에서 여러 에이전트를 사용하려면 각 에이전트에 별도의 Bot을 연결하세요.

## Bot 연결

에이전트 owner, 워크스페이스 owner, admin이 연결을 시작할 수 있습니다.

1. **에이전트**를 열고 Feishu에 연결할 에이전트를 선택합니다.
2. **연동**으로 이동해 **Feishu에 연결**을 클릭합니다.
3. Feishu로 QR 코드를 스캔하고 승인을 확인합니다.
4. Multica로 돌아옵니다. 페이지에 **Feishu에 연결됨**이 표시되면 사용할 수 있습니다.

QR 코드는 일회용 자격 증명이며 만료되면 다시 생성하면 됩니다. 이미 연결된 에이전트에는 스캔 메뉴가 다시 표시되지 않습니다. 이름이나 권한을 조정하려면 **Feishu에서 관리**를 클릭하세요.

<Callout type="info">
현재 새 연결은 중국 본토 버전 Feishu에서만 만들 수 있습니다. 기존 국제 버전 Lark 연결은 계속 사용하고 관리할 수 있습니다.
</Callout>

## 처음 사용

멤버가 Bot에 처음 메시지를 보내면 계정 연결 링크를 받습니다.

1. 링크를 열고 Multica에 로그인합니다.
2. 연결할 워크스페이스 계정을 확인합니다.
3. Feishu로 돌아가 메시지를 다시 보냅니다.

연결을 마쳐야 Multica가 메시지를 보낸 워크스페이스 멤버를 확인할 수 있습니다. 멤버가 아닌 사람은 Bot을 사용할 수 없습니다.

## Feishu에서 작업 요청

### DM

Bot에 바로 메시지를 보내면 됩니다. 연속된 메시지는 같은 Multica 대화에 유지되며 에이전트의 답변도 현재 대화로 돌아옵니다.

### 그룹 채팅

먼저 Bot을 그룹 채팅에 추가한 뒤 `@Bot`과 요구 사항을 함께 작성합니다. Bot은 자신을 명시적으로 @멘션한 메시지에만 응답합니다. 실행할 때는 현재 대화에서 읽을 수 있는 최근 컨텍스트를 함께 사용합니다.

### 태스크 만들기

다음과 같이 보냅니다.

```text
/issue 로그인 후 리디렉션 문제 수정
Safari에서 로그인에 성공해도 로그인 페이지에 계속 머뭅니다.
```

첫 줄이 제목이 되고 나머지 내용이 설명이 됩니다. `/issue`만 보내면 Multica가 이전 메시지를 제목으로 사용하려고 시도합니다.

## 연결 관리

**설정 → 메신저 → Lark**에서 워크스페이스에 연결된 Bot을 확인할 수 있습니다. 워크스페이스 owner와 admin은 여기서 연결을 해제할 수 있고, 에이전트 owner도 해당 에이전트의 **연동** 페이지에서 자신의 Bot을 관리할 수 있습니다.

연결을 해제하면 Bot이 새 메시지를 받지 않습니다. 기존 대화와 감사 기록은 함께 삭제되지 않습니다.

## 인박스 알림

인박스 알림은 각 구성원이 명시적으로 선택한 대상을 사용합니다. 알림을 만든 에이전트, 자동화 또는 구성원에 따라 대상이 바뀌지 않습니다.

1. **인박스** 페이지 메뉴에서 **Feishu 알림**을 엽니다.
2. 이미 Feishu에서 연결한 에이전트 봇을 선택하거나 전용 인박스 봇을 설치합니다. 전용 봇은 에이전트에 연결되지 않습니다.
3. 대상을 선택하고 저장한 뒤 **테스트 보내기**로 도달 여부를 확인합니다.

모든 알림은 이 하나의 대상으로 전송됩니다. 대상이 없거나 비활성화되면 알림은 Multica 안에만 남으며, 가장 최근에 연결한 봇으로 자동 전환되지 않습니다.

각 알림은 영구적인 전송 기록을 만듭니다. 실패하면 제한된 백오프로 재시도하며 수동으로도 다시 시도할 수 있습니다. 재시작 후에도 미완료 전송을 이어가고, 여러 복제본이 같은 기록을 동시에 처리하지 않습니다. 전송 실패로 인박스 항목이 삭제되거나 원래 작업/이슈 요청이 차단되지 않습니다.

대상을 교체하거나 해제하면 이전 대상의 대기 중 기록은 취소됩니다. 이미 전송 중이던 요청은 도착할 수 있고, Feishu가 수락한 뒤 타임아웃되면 중복이 생길 수 있습니다. 전송 기록은 이러한 상태를 보여주지만 Multica는 종단 간 exactly-once를 보장하지 않습니다.

마이그레이션은 기존 Feishu 연결에서 대상을 추론하지 않습니다. 각 구성원은 처음 사용할 때 명시적으로 선택해야 합니다. 롤백하려면 자신의 대상을 비활성화하면 되며 Multica 인박스는 계속 동작합니다. 데이터베이스 롤백은 대상/전송 테이블과 전용 봇 행을 삭제합니다.
## 자체 호스팅 설정

Multica Cloud에는 추가 설정이 필요 없습니다. 자체 호스팅 환경에서는 Bot 자격 증명 암호화에 사용할 키를 먼저 설정해야 합니다.

```dotenv
MULTICA_LARK_SECRET_KEY=<base64로 인코딩한 32바이트 키>
```

다음과 같이 생성할 수 있습니다.

```bash
openssl rand -base64 32
```

API 서비스를 다시 시작한 뒤 에이전트의 **연동** 페이지에서 Bot을 연결하세요. 이 키는 장기간 보관해야 합니다. 키를 바꾸거나 잃어버리면 기존 자격 증명을 복호화할 수 없으므로 다시 연결해야 합니다.

`MULTICA_LARK_HTTP_BASE_URL`과 `MULTICA_LARK_CALLBACK_BASE_URL`은 프록시, 테스트 같은 특수한 배포에서만 사용하며 일반적으로 설정할 필요가 없습니다.

### Bot union_id와 멘션 판별

Multica 봇이 여러 개 있는 그룹에서 @ 멘션을 올바른 봇에 연결하려면 해당 봇의 안정적인 `union_id`가 필요합니다. 연결 시 수집하며, 기존 설치는 업그레이드 후 첫 부팅에서 Feishu 연락처 API로 보완합니다. 이 호출에는 앱 권한 `contact:user.base:readonly`가 필요하고 봇이 앱의 권한 범위에 포함되어야 합니다. Feishu가 거부하면(`41050 no user authority error`) 설치는 Feishu 진단 정보와 함께 *union_id 사용 불가*로 표시되고, 이후 재시작에서는 호출하지 않으며 멘션은 `open_id` 매칭으로 대체됩니다. DM과 봇이 하나뿐인 그룹은 영향을 받지 않습니다. 봇이 여러 개인 그룹에서는 멘션이 다른 봇으로 귀속될 수 있습니다.

권한을 부여하고 새 앱 버전을 게시한 뒤 재시도를 한 번 강제합니다:

1. `docker-compose.selfhost.yml`과 같은 디렉터리의 `.env`에 `MULTICA_LARK_UNION_ID_BACKFILL_FORCE=true`를 설정하고(compose가 backend 컨테이너로 전달합니다) API 서버를 재시작합니다.
2. 로그에 해당 설치의 `lark backfill: stamped union_id`가 나타나는지 확인합니다. 마커가 지워지고 이후 부팅에서는 다시 시도하지 않습니다.
3. 변수를 제거하고 평소대로 재시작합니다. 강제 재시도가 타임아웃이나 5xx로 실패해도 마커는 지워지므로 다음 일반 재시작에서 다시 시도합니다.

## 자주 묻는 문제

- **연결 버튼이 없음**: 현재 계정이 에이전트 owner, 워크스페이스 owner, admin인지 확인하고 자체 호스팅 키가 설정되었는지 확인합니다.
- **QR 코드 만료**: 팝업을 닫고 연결을 다시 시작합니다.
- **Bot이 계정 연결을 요구함**: 연결 링크를 열고 해당 워크스페이스의 Multica 계정으로 로그인합니다.
- **Bot이 실행되지 않음**: 에이전트가 보관 처리되었는지, 사용하는 [런타임](/daemon-runtimes)이 온라인인지 확인합니다.
- **Bot이 전혀 응답하지 않음**: 앱은 롱 커넥션으로 이벤트를 보내야 하며, Multica에는 webhook 수신 주소가 없습니다. Feishu/Lark 개발자 콘솔에서 **이벤트 및 콜백 → 이벤트 설정**을 열어 구독 방식이 요청 URL이 아닌 롱 커넥션인지, `im.message.receive_v1`이 구독되어 있는지, 해당 설정이 포함된 버전이 게시(테넌트 심사가 필요한 경우 승인)되었는지 확인합니다. 요청 URL로 설정된 앱도 연결은 성공하고 '연결됨'으로 표시되지만 메시지는 한 건도 도착하지 않습니다.
