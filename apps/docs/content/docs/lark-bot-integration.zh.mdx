把一个 Multica 智能体连接成飞书 Bot 后，团队成员可以在飞书里私聊它、在群里 @ 它，也可以用 `/issue` 创建任务。对话和执行记录仍会保存到 Multica 工作区。

每个 Bot 只对应一个智能体。需要在飞书中使用多个智能体时，分别为它们连接 Bot。

## 连接 Bot

智能体的所有者、工作区 owner 和 admin 可以发起连接：

1. 打开 **智能体**，选择要接入飞书的智能体。
2. 进入 **集成**，点击 **绑定到飞书**。
3. 用飞书扫描二维码并确认授权。
4. 回到 Multica。页面显示 **已连接到飞书** 后即可使用。


二维码为一次性凭证，过期后重新生成即可。已经连接的智能体不会再次显示扫码入口；需要改名或调整权限时，点击 **在飞书中管理**。

<Callout type="info">
目前只开放中国大陆版飞书的新连接入口。已有的国际版 Lark 连接仍可继续使用和管理。
</Callout>

## 第一次使用

成员第一次给 Bot 发消息时，会收到一个账号绑定链接：

1. 打开链接并登录 Multica。
2. 确认要关联的工作区账号。
3. 回到飞书，再发送一次消息。

绑定后，Multica 才能确认消息来自哪位工作区成员。非成员无法使用 Bot。

## 在飞书中交代工作

### 私聊

直接给 Bot 发消息即可。连续消息保留在同一段 Multica 对话中，智能体的回复也发回当前对话。

### 群聊

先把 Bot 加入群聊，再 `@Bot` 并写下要求。Bot 只会响应明确 @ 它的消息；执行时会结合当前会话中可读取的近期上下文。

### 创建任务

发送：

```text
/issue 修复登录后的跳转问题
Safari 登录成功后仍然停留在登录页。
```

第一行作为标题，其余内容作为描述。只发送 `/issue` 不会创建任务；Bot 会回复用法提示。

## 管理连接

打开 **设置 → 消息渠道 → 飞书** 可以查看工作区内已连接的 Bot。工作区 owner 和 admin 可以在这里断开连接；智能体所有者也可以回到该智能体的 **集成** 页面管理自己的 Bot。

断开后，Bot 不再接收新消息，已有的对话和审计记录不会随之删除。

## 收件箱通知

收件箱通知使用每位成员明确选择的出口，不会因为通知来自不同智能体、自动化任务或其他成员而改变。

1. 打开 **收件箱** 页面菜单，选择 **飞书通知**。
2. 选择一个已在飞书中完成绑定的智能体机器人，或安装专属收件箱机器人。专属机器人不依附任何智能体。
3. 选择出口并保存。使用 **发送测试** 确认机器人可以联系到你。

所有来源的收件箱通知都会走这个出口。未设置出口或已禁用时，通知只保留在 Multica 站内，不会回退到最近绑定的机器人。

每条收件箱通知都会写入持久化投递记录。失败后会按有限次数退避重试，也可以在同一个对话框中手动重试；服务重启后会恢复未完成投递，多实例不会并发消费同一条记录。投递失败不会删除站内收件箱消息，也不会阻塞创建它的任务或工单请求。

替换或解绑出口会取消旧目标的待发记录。目标更换时已经在发送中的请求仍可能送达；飞书已接收但请求超时也可能产生重复。投递记录会显示这些状态，但 Multica 不承诺端到端 exactly-once。

迁移不会根据已有的飞书绑定推断出口，每位成员首次启用外部收件箱通知时都需要显式选择。回滚时禁用自己的出口即可，站内收件箱不受影响；数据库回滚会删除出口、投递记录表以及专属机器人记录。
## 自托管配置

Multica Cloud 无需额外配置。自托管部署需要先设置一个用于加密 Bot 凭据的密钥：

```dotenv
MULTICA_LARK_SECRET_KEY=<base64 编码的 32 字节密钥>
```

可以这样生成：

```bash
openssl rand -base64 32
```

重启 API 服务后，再从智能体的 **集成** 页面连接 Bot。该密钥需要长期保存：更换或丢失后，已有凭据无法解密，需要重新连接。

`MULTICA_LARK_HTTP_BASE_URL` 和 `MULTICA_LARK_CALLBACK_BASE_URL` 只用于代理、测试等特殊部署，正常情况下不需要设置。

### Bot union_id 与 @ 消歧

群里同时有多个 Multica 机器人时，要把一次 @ 提及对应到正确的 Bot，需要该 Bot 稳定的 `union_id`。Multica 在连接时获取它，升级后首次启动也会通过飞书通讯录接口为已有安装补齐。该调用要求应用具备 `contact:user.base:readonly` 权限，且 Bot 位于应用的通讯录权限范围内。若飞书拒绝（`41050 no user authority error`），安装会被标记为「union_id 不可用」并记录飞书返回的诊断信息，之后重启不再重复调用，@ 提及退化为 `open_id` 匹配。私聊和只有一个 Bot 的群不受影响；多 Bot 群中提及可能被归属到错误的 Bot。

授予权限并发布新应用版本后，强制重探一次：

1. 在 `docker-compose.selfhost.yml` 同目录的 `.env` 中设置 `MULTICA_LARK_UNION_ID_BACKFILL_FORCE=true`（compose 会把它透传给 backend 容器），然后重启 API 服务。
2. 确认日志出现该安装的 `lark backfill: stamped union_id`。标记会被清除，之后启动不再探测。
3. 去掉该变量并按正常方式重启。若强制重探遇到超时或 5xx，标记同样会被清除，下一次普通重启会再次尝试。

## 常见问题

- **没有绑定按钮**：确认当前账号是智能体所有者、工作区 owner 或 admin，并检查自托管密钥是否已配置。
- **二维码失效**：关闭弹窗后重新发起连接。
- **Bot 要求绑定账号**：打开绑定链接并使用该工作区的 Multica 账号登录。
- **Bot 不执行**：检查智能体是否已归档，以及它使用的[运行时](/daemon-runtimes)是否在线。
- **Bot 完全不回复**：应用必须通过长连接推送事件，Multica 没有 webhook 接收地址。打开飞书开发者后台的 **事件与回调 → 事件配置**，确认订阅方式是使用长连接接收事件而不是请求地址，`im.message.receive_v1` 已订阅，并且包含该配置的版本已发布（企业需要审核时还要通过审核）。配成请求地址的应用照样能绑定、照样显示「已连接」，但一条消息都收不到。
- **飞书收件箱通知收不到**：打开收件箱页面菜单，确认出口处于启用状态并点击 **发送测试**。同一对话框会列出最近投递和最后一条错误。未设置出口时，通知只会留在 Multica 站内。
- **通知发到了错误的机器人**：显式替换出口，旧目标的待发记录会被取消；飞书已经接收的进行中请求仍可能送达。
